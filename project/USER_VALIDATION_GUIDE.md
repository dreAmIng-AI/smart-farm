# Core v0.1 사용자 검증 가이드

## 목적

이 가이드는 Core v0.1의 작업 흐름이 실제 농장 운영자가 이해하고 사용할 수 있는지 확인하기 위한 최소 검증 시나리오입니다. 결과는 제품 개선에 사용하며, 현재의 Draft TaskTemplate은 농업 처방이나 자동 실행 지시가 아닙니다.

## 준비

- Farm owner로 로그인할 계정 1개
- 초대 수락을 확인할 다른 이메일 주소 1개(사전 Supabase Dashboard 계정 생성 불필요)
- 사진 첨부를 확인할 수 있는 JPEG, PNG 또는 WebP 파일 1개(10MB 이하)
- 실행 주소: 로컬 개발 환경은 `http://localhost:3000`, 배포 환경은 해당 서비스 주소

검증 전에 owner 계정은 Farm이 없거나, 새 Farm을 만들어 이전 테스트 기록과 구분합니다.

## 1. 계획과 Today 흐름

1. owner로 로그인하고 Farm을 만듭니다.
2. Farm에 CropCycle을 만듭니다. 개발 검증용 예시는 `strawberry` / `Seolhyang` / `Protected cultivation`입니다.
3. Draft TaskTemplate을 적용해 FarmTask를 생성합니다.
4. 일정에서 작기 전체 작업과 `draft` 검증 상태 표시를 확인합니다.
5. Today에서 오늘 예정 작업과 지연 작업이 구분되어 보이는지 확인합니다.

성공 기준: 작물별 조건을 Core 코드에서 선택하지 않아도 Template 기반 작업이 일정과 Today에 나타납니다.

## 2. 실행·기록·문제·이력 흐름

1. Today 또는 일정에서 FarmTask 하나를 열어 이유, 시기, 우선순위, 근거, 검증 상태를 확인합니다.
2. 결과를 `완료`로 기록하고 짧은 메모를 남깁니다.
3. 다른 작업은 `문제 있음`으로 기록하고, 필요한 경우 사진을 첨부합니다.
4. 열린 IssueRecord에서 후속 확인 FarmTask를 하나 만듭니다.
5. 이력에서 ActionLog, IssueRecord, 후속 작업의 시간 순서와 연결 관계를 확인합니다.

성공 기준: 결과 기록이 작업 상태에 반영되고, 문제는 후속 작업과 이력으로 추적됩니다.

## 3. 협업과 초대 흐름

1. owner로 로그인한 상태에서 Farm 구성원과 초대 관리에서 다른 이메일을 `farmer`로 초대합니다.
2. 생성된 링크를 공유·복사하거나 이메일 앱에서 직접 보냅니다. 자동 이메일 발송은 하지 않습니다.
3. 링크를 받은 신규 사용자는 초대받은 동일 이메일과 본인 비밀번호를 입력해 계정을 설정합니다. 기존 계정이 있으면 같은 화면의 로그인으로 진행합니다.
4. 수락 후 초대받은 Farm이 자동으로 열리고, 해당 계정에서 CropCycle·작업 정보를 확인합니다.
5. Supabase Email confirmation이 켜진 환경에서는 이메일 인증 후 같은 초대 링크를 다시 열어 수락합니다.
6. owner는 보낸 초대의 `새 링크 만들기`를 선택해, 이전 링크가 무효화됨을 확인합니다.
7. 재발급 이전 링크는 수락에 실패하고, 새 링크는 수락할 수 있는지 확인합니다.

권한 기준: owner는 admin/farmer 초대를 관리할 수 있고, admin은 farmer만 관리할 수 있으며, farmer는 구성원 관리 UI를 볼 수 없습니다.

## 관찰 질문

각 참가자에게 다음 다섯 가지를 1~5점과 한 문장으로 기록합니다.

| 질문 | 점수 | 메모 |
|---|---:|---|
| 작기 전체 계획이 왜 필요한지 이해했는가? |  |  |
| Today의 작업이 현장에서 우선순위를 정하는 데 도움이 되는가? |  |  |
| 결과와 문제 기록의 입력 부담은 적절한가? |  |  |
| 후속 작업과 이력이 다음 행동을 결정하는 데 도움이 되는가? |  |  |
| 다른 구성원을 초대하고 권한을 구분하는 방식이 이해되는가? |  |  |

## 결과 기록

| 항목 | 결과 | 발견한 문제 | 재현 절차 | 중요도 |
|---|---|---|---|---|
| 계획·Today | 통과 / 실패 |  |  | P0 / P1 / P2 |
| 결과·문제·이력 | 통과 / 실패 |  |  | P0 / P1 / P2 |
| 초대·권한 | 통과 / 실패 |  |  | P0 / P1 / P2 |

- **P0**: 데이터를 잃거나, 권한이 잘못 적용되거나, 핵심 작업 흐름을 완료할 수 없음
- **P1**: 흐름은 완료되나 사용자 검증에서 반복적으로 혼란·부담을 만듦
- **P2**: 문구, 배치, 편의성처럼 사용을 막지 않는 개선

발견된 항목은 하나의 Issue와 하나의 Branch/PR로 분리합니다. Weather, AI, Disease, Sensor, Market 제안은 Core v0.1 결함으로 처리하지 않고 독립 Lab 후보로 기록합니다.

## 안전 및 데이터 경계

- Draft fixture와 화면의 작업 정보는 실제 농업 처방으로 사용하지 않습니다.
- 사진·메모에 불필요한 개인정보나 민감한 농장 정보를 넣지 않습니다.
- 초대 링크는 초대받은 이메일 계정에만 전달합니다. 링크를 분실하면 재발급하고 이전 링크를 폐기합니다.
