# dreAmIng 스마트농업 개발 착수 의사결정서 — 합의본

- 상태: `DECIDED WITH TBD IDENTITIES`
- 목적: 첫 개발 범위와 기술·데이터·AI 기준을 고정한다.

## 1. 제품 기준

### 1.1 한 문장 정의

설향 딸기 시설재배 농가가 농장과 작기를 등록하면 현재 생육단계와 검토된 작업 기준을 바탕으로 오늘 해야 할 작업을 보여주고, 실행 결과와 문제를 기록해 후속 작업으로 연결하는 농작업 실행관리 서비스입니다.

### 1.2 해결하려는 문제

- 농업정보가 여러 플랫폼에 흩어져 있다.
- 현재 농장에 필요한 정보인지 판단하기 어렵다.
- 정보를 확인해도 실제 작업으로 연결되지 않는다.
- 작업 결과와 문제를 지속적으로 기록하기 어렵다.
- 기록이 다음 판단과 작업에 활용되지 않는다.

### 1.3 핵심 가치

```text
농장에 맞는 정보 선별
→ 오늘의 우선 작업
→ 실행 결과 기록
→ 후속 작업과 이력
```

서비스의 가치는 정보량이 아니라 **개인화·우선순위·작업 연결·기록 축적**입니다.

## 2. 초기 대상

- 작목: 설향 딸기
- 재배방식: 시설재배
- 사용자: 신규 또는 소규모 시설재배 농가를 포함한 현장 농업인
- 기기: 모바일 우선
- 초기 검증 범위: 특정 시·군, 작목반 또는 농가 그룹 1곳

화면과 홍보에서 “초보 농업인”이라는 표현을 과도하게 강조하지 않습니다.

## 3. MVP 포함 범위

### 첫 수직 기능 필수

- 농장 등록
- 작기 등록
- 품종·정식일·생육단계 입력
- 농업 전문가가 검토한 규칙 기반 작업 생성
- 오늘의 작업 확인
- 완료·문제 기록
- 사진 또는 짧은 메모
- 작업 이력
- 문제 발생 시 후속 확인 작업

### 첫 수직 기능 이후

- 외부 날씨 1개 데이터원
- 설향 생육단계별 공식 재배정보 1개 데이터원
- 작업 근거와 공식 출처
- 간단한 주간 요약

## 4. 제외·연기 범위

## 5. 화면 범위

최종 메뉴 목표:

```text
오늘 | 농장 | 작업 | 정보 | 기록
```

첫 수직 기능에서 실제 구현:

```text
오늘 | 농장 | 작업 | 기록
```

`정보` 메뉴는 공식정보 통합 기능이 준비된 뒤 노출합니다.

## 6. Mission Card와 Action Log

초기 Mission Card는 별도 핵심 객체로 만들지 않고 `FarmTask`의 UI 표현으로 사용합니다.

```text
FarmTask 데이터
→ Mission Card UI
→ ActionLog 기록
```

FarmTask는 다음 질문에 답해야 합니다.

- 무엇을 해야 하는가?
- 왜 해야 하는가?
- 언제 해야 하는가?
- 어떤 근거가 있는가?
- 우선순위와 안전 상태는 무엇인가?
- 어떤 결과를 기록해야 하는가?

## 7. 데이터 구분 원칙

### 공식정보

공공 API, 공식 재배기술, 공식 기상·병해충 정보

### 농장정보

농장·작기, 작업 결과, 문제, 사진, 메모, 향후 센서 데이터

### 서비스 분석정보

오늘의 작업, 우선순위, 확인 필요 항목, 후속 작업, 요약

화면과 데이터에서 다음 라벨을 구분합니다.

- 공식정보
- 농장 기록·측정값
- 서비스 분석

## 8. 기술 결정

| 항목 | 결정 |
|---|---|
| Web | Next.js + TypeScript |
| Database/Auth/Storage | Supabase |
| Deployment | Vercel |
| Repository | Monorepo |
| DB naming | snake_case |
| TypeScript/API | camelCase |
| Time storage | UTC |
| Display timezone | Asia/Seoul |
| Merge | Squash and merge |

외부 API는 프런트엔드에서 직접 호출하지 않습니다.

```text
Next.js Server / Integration Layer
→ Adapter
→ Normalizer
→ Supabase Cache
→ 화면·작업 규칙에서 사용
```

## 10. 첫 외부정보 적용

첫 수직 기능 완료 후 다음 두 종류만 우선 검토합니다.

1. 외부 날씨
2. 설향 생육단계별 공식 재배정보

외부정보는 독립 포털이 아니라 작업 생성의 근거로 사용합니다.

```text
공식정보 또는 외부 데이터
→ 농장·작기 조건 필터링
→ FarmTask 생성 또는 우선순위 조정
→ 근거와 출처 표시
```

API 존재만으로 상업적 사용·가공·재배포가 가능하다고 판단하지 않습니다.

## 11. 사용자와 권한

초기 역할은 두 개로 구분합니다.

- Farmer: 자신의 농장·작기·작업·기록 관리
- Admin: 농가 목록과 최소 운영 상태 확인

첫 수직 기능에서는 권한 구조만 분리하고 관리자 화면은 최소 범위로 구현합니다.

## 12. 검증 데이터

- 가상·공개 데이터로 개발을 시작합니다.
- 실제 농가 인터뷰와 작업 기록을 순차 반영합니다.
- 실제 농가 데이터는 초기 모델 성능보다 데이터 필드, 누락 패턴, 현장 용어, 입력 방식, 업무 흐름 검증에 우선 사용합니다.
- 가상 데이터와 실증 데이터를 명확히 구분합니다.

## 13. 첫 AI 기능

AI는 첫 수직 기능에 포함하지 않습니다.

규칙 기반 작업과 기록 흐름이 작동한 뒤 다음 기능부터 적용합니다.

- 최근 기록 요약
- 누락 정보 확인
- 추가 질문
- 다음 확인 작업 제안

AI가 해서는 안 되는 역할:

- 병명 확정
- 농약 자동 처방
- 데이터 없는 농장 상태 단정
- 공식자료에 없는 수치 생성
- 출처 없는 작업 생성
- 전문가 검토 없는 위험 작업 지시
